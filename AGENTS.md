## dacospace

Daily learning loop: lesson -> lab -> interview. Next.js web app + stdio MCP
server sharing `lib/core/`. Interview questions are markdown in `questions/`
(format in `questions/README.md`), personal data in `data/` (gitignored).

The lab content and CLI live in a sibling `java-scale-lab` checkout (`DACOSPACE_LAB_DIR`).
dacospace parses its `PROGRESS.md` table and the `# Mission NN · Title` /
`# Lesson NN · Title` headings; keep both repos' formats in sync.

- `lib/server/` spawns `./lab`. Every new subcommand must be added to the
  allowlist in `lib/core/lab-commands.ts` with a test; never run through a shell.
- Child processes get `childEnv()`: Next.js sets `PORT=4120`, which a spawned
  Spring app would otherwise take over.
- The server binds 127.0.0.1 and `lib/server/guard.ts` checks Host/Origin and the
  `x-dacospace` header. Keep both.

- Hosted mode (`lib/core/hosted.ts`, the public Vercel demo): no disk writes, no spawns. Any new
  server action calls `assertLocal()`, any new API route goes through `rejectUnlessLocal()`.
  Hosted pages read `content/` (generated by `pnpm sync-content`, allowlist only); never hand-edit it.
- UI text goes through `lib/i18n/messages.ts` (en + tr, same keys). A new or changed question needs its
  `questions/tr/<id>.md` updated too; keep technical terms in English there. The same goes for lab content:
  `content/tr/<repo>/<path>` mirrors `content/<repo>/<path>`, and `tests/content-tr.test.ts` fails when they drift.
- Verify: `pnpm test && pnpm lint && pnpm typecheck && pnpm build`.
- Maintainer notes (only if present on this machine): `~/projects/cortex/playbooks/factory.md`
  and `~/projects/cortex/projects/dacospace.md`.
